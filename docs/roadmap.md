# 分阶段路线 — DSH 服务端登录插件

已完成 **里程碑 1（蓝图 + 脚手架）**、**P1 认证+审核**、**P2 桌面+FS**、**P3 单 DSH 启动**。以下阶段按序推进。

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P1 认证+审核** ✅ | 注册→管理员审核→登录/登出；管理台 UI | 用户可被审核并登录 |
| **P2 桌面+FS** ✅ | 文件树/目录 CRUD/上传，落实每用户隔离 | 用户落到自己的文件桌面 |
| **P3 单 DSH 启动** ✅ | 每用户/每文件夹拉起一个主 DSH + 回环端口 + 反向代理 + 停止/状态 | 从文件夹启动并使用 DSH |
| **P4 每文件夹插件** | 桌面根插件列表+勾选，持久化 `folder_plugins` 并注入 patch | 按项目选插件 |
| **P5 守护/双 DSH（崩溃接管）** | 守护 headless DSH、存活检测、崩溃诊断→修复会话日志→修复根因→resume 接手会话、post-restart 命令握手 | 主 DSH 崩溃/装插件重启时守护接管、修复并续接对话 |
| **P6 域名/nginx** | 自定义域名验证(ACME)、nginx 配置生成、代理路径 origin 重写 | 自定义域名服务用户 DSH |
| **P7 硬隔离** | 每用户 OS 账号/容器或收窄 Landlock 读授权 | 闭合越权读缺口 |

P5 关键子任务：确认 headless DSH 的 resume 入口（`--resume <sessionId>` flag 或 session 服务），以及跨进程存活检测（心跳/端口探测）的具体形态。
